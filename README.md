# 枝叶学习笔记

面向 Apple 芯片 Mac 的本地学习笔记软件。当前本地试用版本 **1.0.4**，支持紧凑写作布局、Typora 风格即时编辑、项目文件夹、标签、可视化思维导图与流程图、GitHub 笔记更新和随机考试。

本文件是软件的统一使用说明。应用源码与个人学习材料分开存放：学习项目、题库副本、论文和交付包保留在相邻的 `../web-notes-extras/`，不作为应用源码提交或随安装包分发。应用内的笔记仍保存在本机笔记库中，移动这些资料文件不会移动或修改浏览器里的笔记。

## 安装与开始使用

提供两种使用方式，任选其一。

### 方式一：下载 App（推荐）

适用于普通使用，无需安装开发环境。提供 Apple Silicon（M1/M2/M3/M4 等）安装包：

- `Zhiye-Notes-1.0.4-arm64.dmg`：打开后将 Zhiye Notes 拖入 Applications。
- `Zhiye-Notes-1.0.4-arm64.pkg`：按照安装向导安装到 Applications。

本次 1.0.4 安装包在本机 `release/` 目录，尚未发布到 GitHub。已发布版本可从 [GitHub Releases](https://github.com/Jianglllri/Notess/releases/latest) 下载。Apple 芯片 Mac 使用 DMG 或 PKG 任一即可。应用采用本地 ad-hoc 签名，未使用 Apple Developer ID 签名或公证，PKG 未做发行证书签名；macOS 首次打开可能提示「无法验证开发者」，请在「系统设置 → 隐私与安全性」中点击「仍要打开」。当前交付不包含 Intel Mac 或 Windows 安装包。

打开应用后会读取本地笔记，并尝试从已配置的公开与私密笔记仓库的 `main` 分支获取笔记。首次加载需要网络，已保存在本机的笔记可以离线编辑。

### 方式二：不下载 App，本地源码启动

适用于开发者或希望从源码运行的用户，需要 Node.js 22.12+。在源码目录执行：

```sh
npm ci
npm run dev        # 浏览器开发预览：浏览器打开 http://127.0.0.1:5173
# 或
npm run desktop    # 构建并启动桌面应用（等价于方式一的本地运行版）
```

- `npm run dev` 为浏览器版：数据保存在本机共享笔记库，上传 GitHub 需填写 Token。
- `npm run desktop` 为桌面版：新版与本机浏览器共用 `~/.zhiye-notes/workspace.json`，优先使用本机已有 GitHub 登录，没有可用登录时再填 Token。
- 本机开发版、预览版与新版桌面 App 共用 `~/.zhiye-notes/workspace.json`；跨设备同步需配置 GitHub 仓库（见「GitHub 导入与更新」）。
- 更多开发、测试与打包命令见「开发与打包」。

## 记录、编辑与保存

默认进入阅读页；点击「即时编辑」后显示目录与正文，中间笔记列表按需展开。左上角「目录」「列表」可分别折叠两栏；拖动分隔线调整宽度，双击恢复默认宽度，聚焦分隔线后也可用方向键调整。布局会记住，窄窗口自动限制侧栏宽度。按 `⌘/Ctrl + K` 展开列表并搜索标题、正文、标签。

- **新建笔记**：点击侧栏「新建笔记」，直接进入正文编辑。导入、发布、随机考试和 HTML 导出统一收在编辑栏「工具 ···」菜单。
- **流程图**：点击编辑栏「流程图」，创建处理步骤、判断菱形、开始 / 结束节点；拖动节点布局，从右侧连接点拖到目标节点绘制箭头，也可用目标下拉框连接。双击节点或连线修改文字，支持删除、撤销、重做及再次编辑。流程图支持节点宽度 80–600、高度 40–360；也可输入尺寸，方向键移动或缩放，撤销／重做。画布可在 50%–200% 缩放，连线随节点移动和缩放更新，旧版流程图按默认尺寸兼容读取。最多 80 个节点和 200 条连线，支持分支与回路。数据以 `zhiye-flow` 代码块保存在 Markdown 中，本应用即时编辑、阅读和 HTML 导出显示离线 SVG；其他 Markdown 软件可能显示源数据。现有 Mermaid / flowchart 代码不会自动转成可视化图。
- **思维导图**：点击编辑栏「思维导图」，在画布选择节点后编辑文字、添加子节点、删除分支或撤销。保存为笔记内的 markmap 标题结构，支持重新编辑、阅读预览与 HTML 导出；最多 80 个节点、6 层，不支持任意 Mermaid/JSON 导图转换或自由拖拽。新图插在文末，已有图原位更新。
- **即时编辑**：默认模式，Markdown 标记随光标显示，离开后展示排版，操作方式接近 Typora。
- **代码块**：输入三个反引号加语言（例如 `python`）后回车，自动创建代码块；`Tab` 缩进四个空格，支持语法高亮、行号和修改语言。工具栏“末尾插入行”可回到普通段落。
- **数学公式**：阅读、双栏预览及考试答案支持 `$...$` 行内公式和 `$$...$$` 公式；导出的 HTML 内嵌 MathML，在现代浏览器中离线显示，无需联网加载公式资源。
- **其他模式**：可以切换 Markdown 源码编辑、双栏预览、阅读。
- **自动保存**：标题、正文、标签和分类修改会保存在本机；显示“已保存到本地”后再关闭。

本地自动保存与 GitHub 上传是两个独立步骤。同一系统用户的新版桌面版和本机浏览器共用磁盘数据：通过 GitHub 同步正文、标题、标签、新增和删除 / 恢复状态；两端都需使用此新版。笔记所在文件夹路径随笔记同步；空文件夹和图片附件请使用 ZIP 备份迁移。

侧栏底部的「备份与同步」默认折叠，点击可展开备份、获取 GitHub 更新和同步入口，软件更新放在最下面。

## 文件夹、项目与标签

点击左侧“我的文件夹”旁的加号新建文件夹。在笔记标题下方选择所属文件夹；输入标签并按回车，一篇笔记可以有多个标签。点击侧栏标签可筛选笔记。

文件夹右侧的「⋯」可改名、移动或删除。管理窗口的「位置（移动到）」支持将整个文件夹移至其他文件夹或顶层，保留全部子目录和笔记，禁止移入自身或后代。笔记标题下的「移动到」可反复切换分类，移动后继续保持当前笔记打开。这些操作仅调整本地分类，不改变 GitHub 文件路径。删除会移除整个文件夹树，并将其中全部笔记移入回收站；恢复笔记后位于未分类。确认上传后同步笔记删除状态，不物理删除 GitHub 文件。刷新已有笔记不会重建删除的目录；远端新增文档仍会按来源目录导入。

从 GitHub 导入的资料按项目整理：

- 每个仓库建立一个项目文件夹，内部保留原目录层级。
- 项目和子目录可以展开或收起，内部直接列出笔记标题，按名称和题号排序；点击标题打开笔记编辑页，悬停显示完整标题。点击项目仍可查看其全部子目录笔记。
- 默认仓库的 `imports/项目名/` 也会作为独立项目展示。
- 旧版已导入笔记在首次刷新时迁移分类，保留内容和 GitHub 关联；之后尊重手动移动的位置。

此前已导入 [RiddleGo/agent-interview-300](https://github.com/RiddleGo/agent-interview-300) 的 319 篇 Markdown 文档，连同一篇来源说明，共 320 条；这些是整理时的数量，不代表当前每个笔记库的实时数量。本地资料副本已移至 `../web-notes-extras/notes-repository/imports/agent-interview-300/`，原始目录索引和来源信息保留在其中。此磁盘路径与应用内项目分类、GitHub 中的来源路径相互独立；本次文件整理没有移动应用内笔记，也没有修改远端文件。

## 本地使用与本地加云端

在「备份与同步 → 仓库与隐私设置」选择使用模式：

- **仅本地**：不自动拉取笔记、不弹上传提醒、不自动检查软件更新，所有已下载笔记继续留在本机；离线新建、编辑、分类、考试和绘图均可用。支持本地 Markdown 导入及 ZIP 备份。主动点击 GitHub 导入或软件更新仍会联网。
- **本地 + GitHub 云端**：启动时获取公开／私密仓库和导入清单，笔记始终先保存本地；联网后由你确认上传新增、修改和删除记录。切换模式不清空正文或同步关联。

本机版本统一存储在 `~/.zhiye-notes`，旧版 IndexedDB 首次打开时自动迁移并保留备份；远程静态部署仍使用所在浏览器的 IndexedDB；它不是自动监控磁盘 Markdown 文件夹的文件系统工具。ZIP 可用于离线迁移，本地图片也包含在备份中。

### 使用本次整理包

整理包现位于源码目录外的 `../web-notes-extras/deliverables/organized-notes/`：`notes-public-organized.zip` 包含 352 篇笔记，`notes-private-organized.zip` 包含 3 篇。这是交付包的内容数量，不是应用当前笔记数；私密包仅在本地保留，不要提交到系统或公开仓库。安装新版后，在「备份与导入 → 从备份导入」选择对应 ZIP，勾选「按云端路径／来源整理已有笔记」，再确认导入。按实际路径和来源匹配，保留本地正文、自行改过的标题、可见性选择和回收站状态；仅同名但来源不同的文档不会被强行合并。重复整理不会重复新增同一份文档。

公开资料按学习基础、算法面试、面试知识、学习复盘和外部资料分类；私密资料单独分类。既有 Markdown 文件路径保持不变，标题、标签、分类和 public/private 写入枝叶元数据。319 篇题库经 Git blob 内容校验与原仓库一致，以 `.zhiye/imports.json` 引用；一篇来源说明保留全文。原始正文没有被重写，源仓库缺少的图片附件不会凭空补齐。

整理后的内容分别保存在 `notes-public` 与 `notes-private` 仓库；系统仓库的旧资料保留。整理包不随应用安装自动导入，私密正文不打入应用或源码 ZIP。

## GitHub 导入与更新

仓库在边栏「备份与同步 → 仓库与隐私设置」中配置，默认分别为：

- 系统与软件更新：[Jianglllri/Notess](https://github.com/Jianglllri/Notess)。
- 公开笔记：[Jianglllri/notes-public](https://github.com/Jianglllri/notes-public)。
- 私密笔记：[Jianglllri/notes-private](https://github.com/Jianglllri/notes-private)。

标题下可选择 public / private。所有上传入口都会检查目标仓库的实际可见性，不匹配或未配置时停止上传。切换分类只改变后续提交目标，不会撤回旧仓库副本或 Git 历史；旧公开内容需另外处理。不要把公开过的内容视作已经保密。

启动和「刷新笔记库」会读取两个笔记仓库。私密仓库需要有权限的本机登录或会话 Token；读取失败不删除本地笔记。工具菜单「导入文档」支持 GitHub 和 vscode.dev 链接，按项目和目录整理，重复导入不会重复添加。

### 外部资料只同步来源记录

- 未改动正文的 GitHub 导入笔记，上传到对应笔记仓库的 `.zhiye/imports.json` 统一清单，记录来源仓库、分支、文件路径、内容 SHA 和下载版本，不重复上传原文。公开和私密清单互相隔离。
- 修改过的外部正文、自建笔记会上传完整正文；标题、标签、置顶、笔记所在文件夹路径以及删除 / 恢复状态一起同步。空文件夹暂不单独同步。
- 新设备读取这些记录后按记录的版本下载正文，并缓存在本地；未联网时仍可使用已下载内容。启动 / 刷新还会检查已跟踪来源文件的新版本，未变化内容复用缓存。来源项目新增的其他文件需重新导入项目。
- 有个人正文修改时保留个人版本，不自动覆盖；失败或来源文件失效会显示提示并保留本地缓存。首次下载失败的记录会提示正文待下载，可恢复网络后刷新；私有来源需在导入窗口输入有权限的 Token 重试导入，不保存 Token。
- 旧版直接从外部链接导入的笔记会在刷新来源时补充关联，保留已有修改。只有 Notess 副本、无法确定原始来源的旧笔记仍按普通笔记同步，不猜测来源，也不自动清空远端旧文件或 Git 历史。
- 来源记录不等同于正文备份：来源被删除且本机没有缓存时可能无法恢复。ZIP 备份仍包含完整本地正文。

### 保存更新到 GitHub

1. 编辑笔记并等待本地保存完成。
2. 点击“同步当前笔记”。已关联的 Markdown 笔记更新原文件，新笔记默认写入 `notes/笔记ID.md`。
3. 桌面版优先使用本机已有 GitHub 登录；没有可用登录时，在仓库窗口填写具有对应仓库 Contents 读写权限的 Token。浏览器版上传需要填写 Token。
4. 提交后会记住远端路径与版本，GitHub 保留提交历史。

仓库设置中的 Token 仅在本次应用会话内存中使用，退出后清除；导入窗口内单独填写的 Token 关闭窗口即清除，不要写入笔记或仓库。

远端文件被其他设备修改或删除时，提交会停止；刷新笔记库并核对远端内容，解决冲突后再提交。拉取时遇到本地未上传内容、标题、标签或删除 / 恢复状态与远端变更冲突，会保留本地并提示冲突。直接在 GitHub 删除文件不会自动删除本地副本；请通过应用内的删除记录同步。

### 跨设备新增、删除与恢复

1. 在网页或桌面版新建 / 修改笔记，或者将笔记移入回收站。
2. 展开「备份与同步」，点击「同步新增 / 修改 / 删除」。列表标明新增、修改 / 恢复和删除，勾选并确认提交。
3. 另一端启动或点击「刷新笔记库」后，会新增对应笔记，或将已删除笔记移入回收站。回收站恢复后的笔记也需确认上传恢复状态。

删除同步使用 Markdown 头部的删除状态记录，保留个人正文或来源记录以便恢复，不物理删除 GitHub 文件；首次从其他仓库导入、从未上传到笔记仓库 的笔记，删除仅影响本机。永久删除已关联笔记前须先完成删除同步，本机会记住已永久删除的来源，刷新不再导入。旧版本中已经永久删除且未留下记录的操作无法追溯补传。

### 每两天上传提醒

首次使用时安排两天后的检查，之后软件运行期间每两天检查新增、修改、删除或恢复的笔记。关闭期间错过的检查在下次打开时补做，检查时间保存在本机。

- 没有改动时不弹窗；有改动时展示可勾选的清单。
- **只有点击“确认更新到 GitHub”才会上传**，不会未经确认自动提交。
- 可以选择“两天后再提醒”，或随时展开「备份与同步」，点击“同步新增 / 修改 / 删除”。
- 成功项记录同步版本，失败项保留并显示原因；冲突不会直接覆盖远端。

检查与批量上传包含来源记录或正文、标题、标签、笔记所在文件夹路径、置顶及删除状态。本地图片附件和空文件夹请通过 ZIP 备份保存。

## 随机考试

点击“随机考试”，选择当前笔记或全部笔记、题数，系统无重复随机抽题。先输入自己的答案，提交后展示参考答案，再自行标记“已掌握”或“还需复习”。当前考试范围不是按项目筛选。

支持 Agent 面试题库的“第 N 题 / 题目 / 讲解”格式，也可以在自己的笔记中使用以下格式：

```markdown
## Q: 什么是闭包？
答案：闭包是函数及其引用的词法环境的组合，使函数能够访问创建它时所在作用域的变量。

## 问题：Promise 有哪些状态？
答案：pending（等待）、fulfilled（成功）、rejected（失败）。由 pending 转换为成功或失败后，状态不再改变。
```

将示例复制到一篇新笔记即可使用。代码围栏中的示例和普通段落不会自动识别为题目。当前不包含 AI 自动判分或考试历史持久化。

## 导出与备份

- **Markdown**：导出单篇 `.md`，不包含本地图片附件。
- **HTML**：导出可阅读的页面，内嵌本地图片。
- **ZIP 备份**：通过侧栏“备份与导入”保存或迁移笔记、文件夹层级及图片附件。

请定期备份；本机共享库不随浏览器缓存清理而删除；远程静态版清除网站数据仍可能丢失笔记。GitHub Pages 需要在仓库设置中另行启用，软件不会自动配置或部署 Pages。笔记更新不等于软件版本更新，桌面版启动时、运行期间每 6 小时会检查 GitHub Releases 的正式版本，有新版时在应用内提示；侧栏「软件更新」也可手动检查。点击下载 DMG / PKG 后退出应用并覆盖安装，保留本地笔记。当前不会后台静默安装，也不会自动退出应用；网络失败可手动重试。

## 开发与打包

软件源码保存在 Notess 系统仓库中；历史笔记副本暂时保留，没有自动迁移或删除。以下命令在软件源码目录执行，需要 Node.js 22.12+：

```sh
npm ci
npm run dev          # 浏览器开发预览（http://127.0.0.1:5173）
npm run desktop      # 构建并启动桌面应用
npm test             # 自动化测试
npm run lint         # 静态检查
npm run typecheck    # TypeScript 类型检查
npm run dist:mac     # 在 macOS 上生成 Apple Silicon DMG 和 PKG
```

`npm run dev`、`npm run build`、`npm test` 执行前会自动运行 `predev` / `prebuild` / `pretest`，把编辑器资源复制到 `public/vditor`，无需手动处理。

主要技术：React、TypeScript、Vite、Electron、IndexedDB、CodeMirror，以及 [Vditor](https://github.com/Vanessa219/vditor) 即时编辑器。桌面编辑与复习流程参考了 [MarkText](https://github.com/marktext/marktext) 和 [Anki](https://github.com/ankitects/anki)。

## 批量管理与来源清单（1.0.1）

在「我的文件夹 → 多选」勾选文件夹和笔记，可混合批量移动／删除。选择父目录时包含后代，重复勾选只处理一次；不能移动到自身或后代，同名文件夹需先改名。删除笔记进入回收站，文件夹树被移除，恢复后可重新分类。

GitHub 导入支持两种方式：

- **来源清单**：新项目归入「来源清单」文件夹；云端 `.zhiye/imports.json` 保存每篇文档的来源链接、分支、路径与版本，本地保存正文。新设备配置相同笔记仓库和权限后获取更新，即可按清单恢复已记录的文件。原仓库新增文件通过「重新扫描导入」添加；当前仍限 Markdown／文本和既有导入容量，并非下载整个代码仓库。
- **完整同步**：上传正文，新设备直接从笔记仓库获取；不自动用外部来源覆盖正文。普通自建笔记同样完整同步。

「管理来源清单」按项目或逐篇切换方式；移动文件夹不自动改变方式。清单文档若有个人修改，则上传完整副本保留修改。来源不可访问时保留本地缓存并提示，不能保证新设备从失效链接恢复。完整方式改回清单不会清除已存在的远端正文或 Git 历史。

两种方式的新增、修改、移动状态需确认上传后同步。未关联云端的本地笔记删除无需联网或 Token，也不上传删除记录；只有已关联云端的笔记才需要同步删除状态。删除是回收站记录，不物理清除 GitHub 历史；public/private 仍分别进入所配置仓库。

### 安全与可靠性修订（1.0.1）

- 即时编辑器禁用 ECharts、WaveDrom 和联网 PlantUML 渲染，代码原文仍可编辑；内置可视化流程图、思维导图保留。依赖更新时安全补丁不匹配会使构建失败，需重新审查。
- 桌面版首次连接仓库及写入使用原生确认窗口。主进程独立检查页面来源、仓库、分支、路径和 public/private 标记；系统仓库只读。仅本地模式禁止上传。
- 清单切换为正文使用一个 Git 提交更新正文和清单，分支发生并发变化会停止；重试可识别已完成的切换。来源变私密会提高本地笔记隐私级别，不会自动撤回以前公开的历史内容。
- 保存采用 250 ms 合并队列，最多一个进行中的快照和一个最新待存快照。关闭页面前尚未完成保存时提示；存储冲突仍需导出备份再处理。
- ZIP 备份在 Web Worker 中生成；超限编辑显示持续提醒，并提供备份和回收站入口。

当前应用目录是唯一开发源码。本机 `web-notes/` 当前没有 `.git`，实际系统 Git 克隆位于 `../web-notes-repositories/system/`；历史发布／笔记仓库克隆保留在相邻的 `web-notes-repositories/`（可通过 `ZHIYE_REPOSITORIES` 指定）。它是发布暂存区，不作为第二份开发源码。测试只收集 `src/**/*.test.{ts,tsx}`，不依赖项目外的个人学习包。

### 导入标题与备份恢复

Markdown、ZIP 和 GitHub 导入统一读取标题：枝叶导出元数据优先，其次是 front matter 的 title、正文标题，最后使用文件名；忽略代码块和 HTML 注释里的标题。完整 ZIP 备份会进入合并确认，保留原始标题、分类及附件。

已有标题异常的题库可在「备份与同步 → 备份与导入 → 整理笔记标题」查看旧名与建议名称，勾选后保存。此操作不修改正文，不自动覆盖手动命名。独立 Markdown 导出也携带标题元数据，避免重新导入时显示 UUID 文件名。

外部 ZIP 最多 1000 篇、单篇展开后 1 MB、正文合计 20 MB；超限会停止整次导入。侧栏 GitHub 导入可选择来源清单或完整正文，自己的笔记仓库则沿用云端设置。
