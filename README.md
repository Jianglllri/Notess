# 枝叶学习笔记

面向 Apple 芯片 Mac 的本地学习笔记软件。当前版本 **0.4.3**，支持卡片记录、Typora 风格即时编辑、项目文件夹、标签、GitHub 笔记更新和随机考试。

本文件是软件的统一使用说明。仓库内导入的学习资料、题库目录索引和来源说明属于学习内容，单独保留。

## 安装与开始使用

提供 Apple Silicon（M1/M2/M3/M4 等）安装包，任选一种：

- `Zhiye-Notes-0.4.3-arm64.dmg`：打开后将 Zhiye Notes 拖入 Applications。
- `Zhiye-Notes-0.4.3-arm64.pkg`：按照安装向导安装到 Applications。

安装包目前在本地项目的 `release/` 目录，尚未发布到 GitHub Releases。应用采用本地 ad-hoc 签名，未使用 Apple Developer ID 签名或公证，PKG 未做发行证书签名；macOS 可能提示无法验证开发者。当前交付不包含 Intel Mac 或 Windows 安装包。

打开应用后会读取本地笔记，并尝试从默认仓库 [Jianglllri/Notess](https://github.com/Jianglllri/Notess) 的 `main` 分支获取笔记。首次加载需要网络，已保存在本机的笔记可以离线编辑。

## 记录、编辑与保存

首页以卡片展示笔记，可以快速记录想法、搜索标题/正文/标签，点击卡片进入完整编辑页。

- **快速记录**：输入内容后点击“记下来”，或按 `⌘/Ctrl + Enter`，保存到本机。
- **即时编辑**：默认模式，Markdown 标记随光标显示，离开后展示排版，操作方式接近 Typora。
- **代码块**：输入三个反引号加语言（例如 `python`）后回车，自动创建代码块；`Tab` 缩进四个空格，支持语法高亮、行号和修改语言。工具栏“末尾插入行”可回到普通段落。
- **数学公式**：阅读、双栏预览及考试答案支持 `$...$` 行内公式和 `$$...$$` 公式；导出的 HTML 内嵌 MathML，在现代浏览器中离线显示，无需联网加载公式资源。
- **其他模式**：可以切换 Markdown 源码编辑、双栏预览、阅读。
- **自动保存**：标题、正文、标签和分类修改会保存在本机；显示“已保存到本地”后再关闭。

本地自动保存与 GitHub 上传是两个独立步骤。桌面版和浏览器版也使用各自的本地数据，迁移时请使用 ZIP 备份。

## 文件夹、项目与标签

点击左侧“我的文件夹”旁的加号新建文件夹。在笔记标题下方选择所属文件夹；输入标签并按回车，一篇笔记可以有多个标签。首页快速记录中的 `#Python #面试` 会被识别为标签，点击侧栏标签可筛选笔记。

从 GitHub 导入的资料按项目整理：

- 每个仓库建立一个项目文件夹，内部保留原目录层级。
- 项目和子目录可以展开或收起，内部直接列出笔记标题，按名称和题号排序；点击标题打开笔记编辑页，悬停显示完整标题。点击项目仍可查看其全部子目录笔记。
- 默认仓库的 `imports/项目名/` 也会作为独立项目展示。
- 旧版已导入笔记在首次刷新时迁移分类，保留内容和 GitHub 关联；之后尊重手动移动的位置。

当前已导入 [RiddleGo/agent-interview-300](https://github.com/RiddleGo/agent-interview-300) 的 319 篇 Markdown 文档，连同一篇来源说明，共 320 条，存放于 `imports/agent-interview-300/`。原始目录索引和来源信息保留在该项目中。

## GitHub 导入与更新

默认笔记库为 [Jianglllri/Notess](https://github.com/Jianglllri/Notess)，分支 `main`。点击“导入 / 仓库设置”可输入导入来源，也可以调整单次发布的目标仓库、分支、文件路径和格式；启动自动获取及两天提醒仍以 Notess 为目标。

### 导入资料

支持 GitHub 仓库主页、`tree` 目录、`blob` 文档及 `vscode.dev/github` 链接，导入 Markdown、Markdown 扩展名文件和 TXT。单次上限为 1000 篇、总计 20 MB、单篇 1 MB；本地笔记库还受 1000 篇笔记、200 个文件夹的限制。

每次启动会自动获取 Notess，也可以点击“刷新笔记库”。重复导入按来源或路径匹配，不重复添加。其他仓库导入的笔记可在本地修改，默认发布到自己的 Notess。

### 保存更新到 GitHub

1. 编辑笔记并等待本地保存完成。
2. 点击“保存更新到 Notess”。已关联的 Markdown 笔记更新原文件，新笔记默认写入 `notes/笔记ID.md`。
3. 桌面版优先使用本机已有 GitHub 登录；没有可用登录时，在仓库窗口填写具有对应仓库 Contents 读写权限的 Token。浏览器版上传需要填写 Token。
4. 提交后会记住远端路径与版本，GitHub 保留提交历史。

Token 仅在当前窗口内存中使用，关闭窗口后清除，不要写入笔记或仓库。

远端文件被其他设备修改或删除时，提交会停止；在“导入 / 仓库设置”中点击“查看远端版本 / 处理冲突”，对照并合并需要保留的内容后再提交。拉取时遇到本地与远端正文同时修改，会保留本地并提示冲突。远端删除文件不会自动删除本地副本。

### 每两天上传提醒

首次使用时安排两天后的检查，之后软件运行期间每两天检查新增或修改的笔记。关闭期间错过的检查在下次打开时补做，检查时间保存在本机。

- 没有改动时不弹窗；有改动时展示可勾选的清单。
- **只有点击“确认更新到 GitHub”才会上传**，不会未经确认自动提交。
- 可以选择“两天后再提醒”，或随时点击“检查待上传笔记”。
- 成功项记录同步版本，失败项保留并显示原因；冲突不会直接覆盖远端。

检查与批量上传包含正文、标题和标签。本地文件夹结构、置顶状态及图片附件不包含在该上传流程中，请通过 ZIP 备份保存。

## 随机考试

点击“随机考试”，选择当前笔记或全部笔记、题数，系统无重复随机抽题。先输入自己的答案，提交后展示参考答案，再自行标记“已掌握”或“还需复习”。当前考试范围不是按项目筛选。

支持 Agent 面试题库的“第 N 题 / 题目 / 讲解”格式，也可以在自己的笔记中使用以下格式：

```markdown
## Q: 什么是闭包？
答案：闭包是函数及其引用的词法环境的组合，使函数能够访问创建它时所在作用域的变量。

## 问题：Promise 有哪些状态？
答案：pending（等待）、fulfilled（成功）、rejected（失败）。由 pending 转换为成功或失败后，状态不再改变。
```

将示例复制到一篇新笔记即可使用。代码围栏中的示例和普通段落不会自动识别为题目。当前不包含 AI 自动判分或考试历史持久化。

## 导出与备份

- **Markdown**：导出单篇 `.md`，不包含本地图片附件。
- **HTML**：导出可阅读的页面，内嵌本地图片。
- **ZIP 备份**：通过侧栏“备份与导入”保存或迁移笔记、文件夹层级及图片附件。

请定期备份；清除应用或浏览器数据可能导致本地笔记丢失。GitHub Pages 需要在仓库设置中另行启用，软件不会自动配置或部署 Pages。笔记更新不等于软件版本更新，软件升级目前使用新的安装包。

## 开发与打包

软件源码目前保存在本地项目及源码 ZIP 中；Notess 主要存放笔记、题库和本说明，不是完整软件源码仓库。以下命令在软件源码目录执行，需要 Node.js 22.12+：

```sh
npm ci
npm run dev          # 浏览器开发预览
npm run desktop      # 构建并启动桌面应用
npm test             # 自动化测试
npm run lint         # 静态检查
npm run dist:mac     # 在 macOS 上生成 Apple Silicon DMG 和 PKG
```

主要技术：React、TypeScript、Vite、Electron、IndexedDB、CodeMirror，以及 [Vditor](https://github.com/Vanessa219/vditor) 即时编辑器。桌面编辑与复习流程参考了 [MarkText](https://github.com/marktext/marktext) 和 [Anki](https://github.com/ankitects/anki)。
